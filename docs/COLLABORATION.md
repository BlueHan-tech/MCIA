# MCIA 协作状态与决策记录

本文件是多个 coding tools 之间共享“当前应如何理解项目”的索引。它不替代实验协议、代码或 run 产物；发生冲突时，先标为待核验，禁止由任一工具静默覆盖。

## 使用规则

1. 开始任务前阅读本文、当前任务相关协议和工作区 diff。
2. 写入决策时使用“已确认 / 已验证 / 已拒绝 / 待验证 / 待核验”之一；不得把运行成功写成方法有效。
3. 每条实质决策写清问题、结论、证据、适用范围和后续动作；链接到协议、代码、run 或论文。
4. `CHANGELOG.md` 记录文件事实；本文记录为什么采用、拒绝或暂停某条路线。
5. 本文中的待核验项是执行门槛，不是可忽略的注释。

## 决策记录

### D-001｜已确认｜2026-09-10

- 问题：C 组是否继续采用“目标截肢者原始 EMG 真值微调”。
- 结论：否。C 定义为健康 DB2 先验在清洁截肢者供体上的无标签适配；目标被试的 glove、验证和测试数据不得用于 C 适配。
- 证据与边界：见 `EXPERIMENT_PROTOCOL.md` §1、§2、§5。该决策不等价于已证明 C 有效。
- 后续：只在 S05/S06 开发阶段选择 C 设置；冻结后才能进行 S03/S07/S09 确认。

### D-002｜已确认｜2026-09-10

- 问题：如何保证文献 baseline 与 MCIA 在本任务上的可比性。
- 结论：SGMD-AAE 与 CP-WOPT 在 DB3 使用同一 200 Hz 包络、同一质量掩码、同一连续角度 TCN；SGMD-AAE 必须标注为任务适配，CP-WOPT 必须标注为 split-transductive。
- 证据与边界：见 `EXPERIMENT_PROTOCOL.md` §7.5、§8。DB3 真实故障区域没有干净真值，因此该数据上不报告补全误差。
- 后续：方法学补全优越性只由健康 DB2 受控遮挡基准判定。

### D-003｜已确认｜2026-09-10

- 问题：是否把 `Observed_only` 纳入正式比较。
- 结论：否。它不进入协议、正式结果表或主链路比较。
- 证据与边界：用户明确决定；后续脚本若仍产生该臂，必须在运行前移除或隔离，不能混入报告。
