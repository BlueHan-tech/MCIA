# Miniforge environment

This project runs as a Python/PyTorch research codebase. The checked-in conda
environment files are:

- `environment.yml`: CPU environment, safest default for Windows.
- `environment-gpu.yml`: NVIDIA GPU environment with PyTorch CUDA 12.8 wheels.

## One-command setup on Windows

From the project root:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_miniforge.ps1 -Variant cpu
```

For an NVIDIA GPU machine:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_miniforge.ps1 -Variant gpu
```

Use the GPU variant for RTX 50-series cards such as RTX 5070.

The script installs Miniforge into `%USERPROFILE%\miniforge3` if `conda.exe` is
not already present, then creates or updates the `apple` environment.

## Manual setup

After installing Miniforge:

```powershell
conda env create -f environment.yml
conda activate apple
```

Or for NVIDIA GPU:

```powershell
conda env create -f environment-gpu.yml
conda activate apple
```

Verify the environment:

```powershell
python -c "import torch, numpy, scipy, pandas, yaml, sklearn, matplotlib; print('torch', torch.__version__, 'cuda', torch.cuda.is_available())"
```

## Data configuration on this workstation

The verified dataset roots (shared with F:/A-SCI/B-SCI) are configured in
`config.yaml`:

- DB2: `F:/A-SCI/Ninapro-DB2`, with `DB2_s1/S1_E1_A1.mat`.
- DB3: `F:/A-SCI/Ninapro-DB3`, with `s5/DB3_s5/S5_E1_A1.mat`.
- Subject metadata: project-local `db2_metadata.csv`.
- Experiment artifacts: `outputs/run/`; datasets are read in place.

This workstation already has a usable `py311` conda environment with PyTorch
and CUDA. Launch from the project root; pipeline stages use the same Python
interpreter as the launcher.

Run the bounded setup check first (no full experiment or run creation):

```powershell
Set-Location E:\paper\MCIA
& D:\work\miniconda\Scripts\conda.exe run --no-capture-output -n py311 python -u scripts/check_data_setup.py
```

The check validates the configured MAT files and metadata, imports all five
stages, preprocesses real DB2/DB3 samples, performs one batch of MCIA training
per database and one Key10 TCN batch, checks gesture splits, and writes a PNG
plus `outputs/setup_validation/report.json`. Its losses only test execution;
they are not experiment results or trained model quality.

When ready for the full experiment (potentially hours), launch:

```powershell
Set-Location E:\paper\MCIA
& D:\work\miniconda\Scripts\conda.exe run --no-capture-output -n py311 python -u scripts/run_all_experiments.py
```

Leave `MCIA_RUN_DIR` unset for a new run. The launcher creates a timestamped
output directory and executes Exp1, transfer, augmentation, angles, and gesture
recognition in order. Set `MCIA_RUN_DIR` explicitly only when continuing an
existing run. Run the full pipeline from Exp1 on a fresh checkout; later stages
require checkpoints generated by preceding stages.
